# whoosh-lpr — распознавание номеров самокатов Whoosh

Консольная программа на C++: читает номера арендных самокатов Whoosh (формат `AA0000`,
две латинские буквы и четыре цифры, например `AK8452`) с обычных фотографий с телефона.
Работает на CPU, обрабатывает файлы и папки пачкой. Внутри две нейросети в формате ONNX:
детектор табличек и модель чтения номера. Обе обучены на фотографиях из этого репозитория.

```
$ scripts/recognize.sh data/raw
AG2938.jpg: AG2938  (спереди, уверенность 95%)
AN7307(2).jpg: номеров в кадре: 2
    PH1865  (спереди, уверенность 96%)
    AN7307  (спереди, уверенность 95%)
PE9147_OR_AN7335(1).jpg: номеров в кадре: 2
    AN7335  (спереди, уверенность 95%)
    PE9147  (спереди и сзади, уверенность 94%)
...
```

## 1. Быстрый старт: распознать фото

Нужны только `git` и Docker. Обученные модели уже лежат в `models/`.

```bash
git clone <адрес этого репозитория> whoosh-lpr
cd whoosh-lpr
scripts/build_cli.sh                 # 5–10 минут: компиляция, тесты, сборка образа
scripts/recognize.sh data/raw/AG2938.jpg
```

`scripts/recognize.sh` монтирует текущую папку в контейнер, поэтому пути к фото
должны быть внутри неё (относительные). Можно передать папку целиком, несколько
файлов или добавить `--json`. То же самое без скрипта:

```bash
docker run --rm -v "/путь/к/фото:/photos:ro" whoosh-lpr .
```

## 2. Как это работает

```
фото ──► детектор ──► рамки табличек ──► выпрямление ──► чтение ──► проверка ──► номер
        (YOLO OBB)    (повёрнутые)       64×256, серое    6 позиций   уверенность
```

1. **Фото** открывается с учётом поворота из EXIF, как в галерее телефона.

2. **Детектор** (`models/detector.onnx`, YOLO11n-OBB, вход 1280×1280) ищет таблички
   и выдаёт *повёрнутые* прямоугольники двух классов:
   * `front` — номер на передней стойке (белая табличка или трафарет прямо по краске);
   * `rear` — двухстрочная табличка на заднем крыле (3 символа сверху, 3 снизу).

   Номер на стойке идёт вдоль неё, поэтому рамки повёрнутые, а не обычные.

3. **Выпрямление.** Каждая рамка перспективно разворачивается в картинку 64×256
   в оттенках серого. Задняя табличка режется на две строки, и они ставятся рядом.
   Так обе таблички выглядят для модели как одна строка из 6 символов.

4. **Чтение** (`models/ocr.onnx`). Номер всегда `AA0000`, поэтому у сети ровно
   6 выходов-позиций: на первых двух возможны только 26 латинских букв, на остальных
   только 10 цифр. Сеть в принципе не может спутать `0` и `O` или `8` и `B`. Каждая
   позиция смотрит на своё место на карте признаков (attention), так что сеть терпит
   неточные рамки детектора.

5. **Ориентация.** Рамка детектора не знает, где у текста начало: номер на стойке может
   быть снят вверх ногами. Поэтому табличка читается в обоих направлениях (задняя —
   в четырёх), а отдельный выход сети оценивает, правильно ли повёрнута картинка.
   Побеждает самое вероятное прочтение.

6. **Уверенность** = вероятность самого слабого символа × вероятность правильного
   поворота. Прочтения ниже порога (по умолчанию 0.3) отбрасываются: это асфальт,
   плитка и стёртая краска, на которые иногда срабатывает детектор. Одинаковые номера
   спереди и сзади объединяются («спереди и сзади»).

**Обучение** (Python, PyTorch, Ultralytics):

* Детектор дообучается из YOLO11n-OBB, предобученного на COCO.
* Модель чтения учится на смеси: половина батча — реальные вырезки табличек,
  половина — синтетические таблички со случайными номерами (`training/ocr_lib.py`,
  открытые шрифты из `training/fonts`). На фото всего 78 номеров, и 12 букв там
  не встречаются ни разу: без синтетики модель их не знала бы.
* Реальные вырезки берутся по **настоящим рамкам детектора** и со случайными сдвигами.
  Рамки детектора заметно свободнее ручной разметки, и модель должна читать именно из них.

Почему C++ даёт те же ответы, что Python: логика один в один повторяет
`training/eval_e2e.py`, а тест `Reference.SameNumbersAsPython` сверяет номера и уверенность
на всех тестовых фото.

## 3. Что лежит в репозитории

```
data/raw/                 168 фото (имя файла = номер; "_OR_" = несколько номеров в кадре)
data/labels/labels.json   разметка: углы каждой таблички и её номер (источник правды)
data/labels/split.json    фиксированное разбиение фото на train / val / test
data/labels/review/       листы для визуальной проверки разметки
models/                   готовые модели: detector.onnx, ocr.onnx + их метрики
src/ include/             C++: детектор, чтение, пайплайн, CLI
tests/                    тесты C++ (gtest) и эталон ответов Python
training/                 Python: подготовка данных, обучение, проверка
  export_yolo.py            разметка → датасет детектора (data/yolo)
  detector.py               обучение детектора (CPU / GPU), экспорт в ONNX
  export_ocr.py             вырезки табличек + рамки детектора → data/ocr
  ocr_lib.py                выпрямление, аугментации, синтетические таблички
  ocr_model.py              сеть чтения и её обучение (CPU / GPU), экспорт в ONNX
  modal_app.py              то же обучение в облаке Modal
  run_all.py                весь конвейер одной командой
  eval_onnx.py              проверка детектора
  eval_e2e.py               проверка всего пайплайна: фото → номер
  make_reference.py         эталон для теста C++
  requirements.txt          версии Python-пакетов
  fonts/                    открытые шрифты для синтетики (+ лицензии)
docker/                   образы для обучения: train-cpu, train-gpu
Dockerfile                образ программы whoosh-lpr (сборка + тесты + рантайм)
scripts/                  train.sh, build_cli.sh, recognize.sh, test.sh
```

Не хранятся в git и создаются при обучении: `data/yolo/`, `data/ocr/`, `runs/`.

## 4. Обучение с нуля на новой машине

Три пути делают одно и то же, разница только в том, где считается:

| | A: CPU | B: своя видеокарта | C: Modal (облако) |
|---|---|---|---|
| Что нужно | Docker | Docker + NVIDIA GPU (лучше от 8 ГБ) + NVIDIA Container Toolkit | Docker + аккаунт Modal |
| Время полного обучения | 10+ часов (оценка, см. 4.2) | около 1 часа | около 1 часа |
| Деньги | 0 | 0 | ≈ $1 (на бесплатных $30 Modal хватает с запасом) |
| Команда | `scripts/train.sh cpu` | `scripts/train.sh gpu` | `scripts/train.sh modal` |

Все пути запускают один и тот же `training/run_all.py` внутри Docker-контейнера
и кладут результат в одно место. Полный прогон в конце копирует новые модели в `models/`.

### 4.1 Подготовка (общая для всех путей)

**Шаг 1. Установить git и Docker.**

* Linux: `git` из пакетного менеджера, Docker Engine по
  [инструкции](https://docs.docker.com/engine/install/). Добавьте себя в группу
  `docker` (`sudo usermod -aG docker $USER`, затем перелогиньтесь), чтобы не писать `sudo`.
* Windows: установите [WSL 2](https://learn.microsoft.com/windows/wsl/install) с Ubuntu
  и [Docker Desktop](https://www.docker.com/products/docker-desktop/) (включите
  «Use the WSL 2 based engine»). Все команды ниже выполняйте **в терминале Ubuntu (WSL)**.
* macOS: Docker Desktop. Подходит для путей A и C (видеокарт NVIDIA на Mac нет).

Проверка: `docker run --rm hello-world` печатает «Hello from Docker!».

**Шаг 2. Скачать репозиторий.**

```bash
git clone <адрес этого репозитория> whoosh-lpr
cd whoosh-lpr
```

В WSL клонируйте в домашнюю папку Linux (`~/whoosh-lpr`), а не на диск Windows
(`/mnt/c/...`): там файлы читаются в разы медленнее, и обучение заметно тормозит.

**Шаг 3. Проверить данные.**

```bash
ls data/raw | wc -l        # 168
ls data/labels             # labels.json  split.json  review
```

**Шаг 4. Пробный прогон (рекомендуется).** Один и тот же конвейер, но 1 эпоха детектора
и 30 шагов модели чтения. Проверяет, что всё ставится и запускается; `models/` не трогает:

```bash
scripts/train.sh cpu --smoke        # или gpu / modal
```

Первый запуск собирает Docker-образ (скачивается около 1–3 ГБ). Сам прогон на CPU
занимает около 10 минут (одна эпоха детектора — около 4 минут). В конце будет строка `done in ... Test photos: ...`: на пробном
прогоне цифры точности почти нулевые, это нормально.

### 4.2 Путь A: обучение на CPU

```bash
scripts/train.sh cpu
```

Ничего, кроме Docker, не нужно. Используются все ядра процессора.
Это самый долгий путь. Одна эпоха детектора на 12-поточном CPU занимает около 4 минут,
а детектор обычно останавливается примерно на 100-й эпохе, то есть 6–8 часов. Затем ещё
несколько часов учится модель чтения. Полный прогон на CPU целиком не замерялся, это оценка. Компьютер можно оставить:
если прервать, начинайте заново (промежуточные результаты лежат в `runs/<имя>/`).

Если хочется быстрее, можно уменьшить объём обучения. Точность будет ниже:

```bash
scripts/train.sh cpu --detector-epochs 60 --ocr-steps 3000
```

### 4.3 Путь B: обучение на своей видеокарте NVIDIA

**Шаг 1. Драйвер.** На хосте должен работать `nvidia-smi`. В Windows ставится обычный
драйвер NVIDIA для Windows, внутри WSL ничего ставить не нужно.

**Шаг 2. NVIDIA Container Toolkit** — даёт Docker доступ к видеокарте.
* Linux: [инструкция](https://docs.nvidia.com/datacenter/cloud-native/container-toolkit/latest/install-guide.html),
  затем `sudo nvidia-ctk runtime configure --runtime=docker && sudo systemctl restart docker`.
* Windows + Docker Desktop: уже встроен, ничего делать не нужно.

**Шаг 3. Проверка:**

```bash
docker run --rm --gpus all nvidia/cuda:12.4.1-base-ubuntu22.04 nvidia-smi
```

Должна напечататься таблица с вашей видеокартой.

**Шаг 4. Обучение:**

```bash
scripts/train.sh gpu
```

Образ `docker/train-gpu.Dockerfile` основан на `pytorch/pytorch:2.5.1-cuda12.4` (около 8 ГБ
при первой сборке). Модели обучались на T4 с 16 ГБ; на картах с 8 ГБ и меньше может не хватить
памяти (ошибка `CUDA out of memory`), тогда запустите шаги с меньшим батчем (раздел 7.3).
Этот путь проверен только частично: образ и код те же, что на CPU и Modal, но на локальной
видеокарте целиком не запускался.

### 4.4 Путь C: обучение в облаке Modal

[Modal](https://modal.com) запускает код на облачной видеокарте NVIDIA T4 с поминутной
оплатой. Новым аккаунтам дают бесплатный кредит, а полное обучение стоит около $1.

**Шаг 1.** Зарегистрируйтесь на modal.com.

**Шаг 2.** Получите токен. Нужен Python с pip на хосте:

```bash
pip install modal==1.3.5
modal setup            # откроет браузер; токен сохранится в ~/.modal.toml
```

Вместо `modal setup` можно задать переменные окружения `MODAL_TOKEN_ID` и
`MODAL_TOKEN_SECRET` (Modal → Settings → API Tokens).

**Шаг 3.** Обучение:

```bash
scripts/train.sh modal
```

Что происходит:
1. Данные загружаются в хранилище Modal (volume `whoosh-lpr`): `data/yolo` и `data/ocr`.
2. Приложение `whoosh-lpr` публикуется (`modal deploy`), и задача запускается через `spawn`.
   Поэтому она **продолжается, даже если ваш компьютер уснул или перезагрузился**.
3. Скрипт ждёт окончания и скачивает результат в `runs/<имя>/`.

Если ожидание прервалось (перезагрузка, обрыв сети), задача всё равно доработает на Modal.
Ход видно в веб-интерфейсе Modal (Apps → `whoosh-lpr`) или командой `modal app logs whoosh-lpr`.
Забрать готовый результат:

```bash
docker run --rm -it --user "$(id -u):$(id -g)" -v "$PWD:/work" -w /work \
  -v "$HOME/.modal.toml:/tmp/home/.modal.toml:ro" whoosh-lpr-train:cpu \
  python training/modal_app.py download --run <имя> --stage ocr   # или detector
```

и продолжить с того же места, не переобучая детектор:
`scripts/train.sh modal --skip-detector` (возьмёт `models/detector.onnx`).

### 4.5 Что происходит во время обучения

`training/run_all.py` выполняет шаги по порядку и печатает каждую команду:

| Шаг | Что делает | Результат |
|---|---|---|
| 1. `export_yolo.py` | фото + разметка → датасет YOLO; фото уменьшаются до 1600 px | `data/yolo/` |
| 2. детектор | дообучение YOLO11n-OBB, вход 1280, до 200 эпох, ранняя остановка через 50 эпох без улучшения; экспорт в ONNX | `runs/<имя>/detector/` |
| 3. `export_ocr.py` | вырезки табличек с запасом вокруг + рамки, которые выдаёт **новый** детектор | `data/ocr/` |
| 4. модель чтения | 10 000 шагов по 192 картинки (половина синтетика), на train+val; экспорт в ONNX и проверка, что ONNX отвечает как PyTorch | `runs/<имя>/ocr/` |
| 5. проверка | детектор отдельно и весь пайплайн на отложенных тестовых фото | печать + `runs/<имя>/e2e_test.json` |
| 6. установка | копирование моделей в `models/`, обновление `tests/data/reference.json` | `models/` |

Имя прогона по умолчанию — дата и время; своё можно задать через `--run`.
Все опции: `python training/run_all.py --help`. Самые полезные:

* `--smoke` — пробный прогон за несколько минут, `models/` не трогает;
* `--skip-detector` — переобучить только модель чтения (детектор из `models/`);
* `--no-install` — не копировать результат в `models/` (чтобы сначала сравнить);
* `--ocr-select` — учить модель чтения только на train и выбирать лучший шаг по val
  (честная оценка на val; по умолчанию val тоже идёт в обучение, как у готовой модели);
* `--detector-epochs`, `--ocr-steps` — объём обучения.

Разбиение на train/val/test зафиксировано в `data/labels/split.json` и не меняется между
запусками: фото одного самоката всегда в одной части, поэтому тест честный, а результаты
разных машин сравнимы.

## 5. Проверка после обучения

```bash
scripts/build_cli.sh     # пересобрать программу с новыми моделями из models/
scripts/test.sh          # все проверки
```

`scripts/test.sh` делает три вещи (всё в Docker):

1. **Тесты C++.** Геометрия рамок плюс `Reference.SameNumbersAsPython`: программа на C++
   прогоняет все тестовые фото и должна выдать те же номера и ту же уверенность (±0.02),
   что Python. Эталон пересчитывается на шаге «установка», поэтому тест проверяет новые модели.
2. **Точность на тестовых фото** (`training/eval_e2e.py`). Печатает строку вида

   ```
   test: numbers read 28/29 = 96.6%, wrong numbers 1, photos fully right 22/23 = 95.7%
   ```

   * `numbers read` — сколько номеров прочитано целиком, все 6 символов;
   * `wrong numbers` — сколько выдано номеров, которых на фото нет (ошибки чтения);
   * `photos fully right` — фото, где найдены все номера и нет ни одного лишнего.

   Номера, которые на фото видны не полностью (`"complete": false` в разметке), не считаются
   ни попаданием, ни ошибкой. Выше строки итогов перечислены фото с ошибками.
3. **Программа** на двух фото.

Отдельно точность на val: `python training/eval_e2e.py --split val` (в образе `whoosh-lpr-train:cpu`
или в своём Python). После обучения с `--final` val уже видела модель, и цифра на ней завышена.

## 6. Программа whoosh-lpr: все опции

```
whoosh-lpr [ОПЦИИ] фото-или-папка...
  -r, --recursive          искать фото и во вложенных папках
  -c, --min-confidence X   порог уверенности чтения 0..1 (по умолчанию 0.3)
      --json               по строке JSON на фото: номера, рамки, уверенность
  -m, --models DIR         папка с detector.onnx и ocr.onnx
  -t, --threads N          потоки CPU (0 = все)
  -v, --verbose            подробный лог
```

* Форматы: JPEG, PNG, WebP, BMP. HEIC (iPhone) не читается — сохраните фото в JPEG
  или включите на iPhone «Камера → Форматы → Наиболее совместимый».
* Модели ищутся так: `--models`, затем переменная `WHOOSH_LPR_MODELS`, затем `models/`
  рядом с программой или в текущей папке.
* Код возврата: 0 — все файлы прочитаны; 1 — какой-то файл не открылся;
  2 — нечего обрабатывать или нет моделей.
* Скорость: 0.3–0.6 с на фото на современном CPU.

Строка `--json`:

```json
{"file":"AG2938.jpg","numbers":["AG2938"],"seconds":0.42,
 "plates":[{"number":"AG2938","plate":"front","confidence":0.95,"detection":0.874,
            "box":[[2372.6,2432.0],[2433.6,2707.4],[2337.0,2728.8],[2276.0,2453.4]]}]}
```

`box` — углы таблички в пикселях фото, по порядку: левый верхний угол текста, правый верхний,
правый нижний, левый нижний.

## 7. Сборка без Docker

### 7.1 Программа на Linux через vcpkg

Нужны CMake ≥ 3.21, Ninja, компилятор с C++20 (GCC 11+ или Clang 14+), `git`, `curl`, `zip`, `pkg-config`.

```bash
git clone https://github.com/microsoft/vcpkg ~/vcpkg && ~/vcpkg/bootstrap-vcpkg.sh
export VCPKG_ROOT=~/vcpkg
cmake --preset release            # зависимости из vcpkg.json; первый раз долго (сборка OpenCV)
cmake --build --preset release
ctest --preset release
~/build/whoosh-lpr/whoosh-lpr data/raw/AG2938.jpg
```

Этот путь описан, но целиком не проверялся (проверены сборки через Docker и через conda-forge).
ONNX Runtime не собирается из исходников: CMake скачивает официальную готовую сборку
(`cmake/onnxruntime.cmake`). Можно указать свою распакованную: `-DORT_ROOT=/путь`.

### 7.2 Программа на Linux через пакеты Ubuntu 24.04

```bash
sudo apt install g++ cmake ninja-build libopencv-dev libcli11-dev nlohmann-json3-dev libspdlog-dev libgtest-dev
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build && ./build/whoosh_lpr_tests
```

Так же собирается Docker-образ (см. `Dockerfile`).

### 7.2a Программа через conda-forge (без прав администратора)

```bash
conda create -p ~/.conda-envs/whoosh-cpp -c conda-forge libopencv onnxruntime-cpp cli11 nlohmann_json spdlog gtest
pip install cmake ninja
P=~/.conda-envs/whoosh-cpp
cmake -S . -B ~/build/whoosh-lpr -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=$P \
      "-DCMAKE_EXE_LINKER_FLAGS=-L$P/lib -Wl,-rpath,$P/lib"
cmake --build ~/build/whoosh-lpr && ~/build/whoosh-lpr/whoosh_lpr_tests
```

Флаги линковщика нужны, потому что conda-библиотеки собраны новым GCC и требуют её `libstdc++`.
conda-forge сейчас ставит OpenCV 5; код поддерживает и 4.x, и 5.x.

### 7.3 Обучение без Docker

```bash
python3.11 -m venv .venv && source .venv/bin/activate
pip install torch==2.5.1 torchvision==0.20.1 --index-url https://download.pytorch.org/whl/cpu   # для CPU
# для GPU вместо строки выше:  pip install torch==2.5.1 torchvision==0.20.1
pip install -r training/requirements.txt
python training/run_all.py --backend cpu      # или gpu / modal
```

Шаги можно запускать и по одному, у каждого скрипта есть `--help`:

```bash
python training/export_yolo.py
python training/detector.py --device 0 --out runs/my/detector --batch 4
python training/export_ocr.py --detector runs/my/detector/detector.onnx
python training/ocr_model.py --device cuda --out runs/my/ocr --final --batch 96
python training/eval_e2e.py --split test --models <папка с обеими моделями>
```

## 8. Данные и разметка

* `data/raw/` — исходные фото, их **не переименовывать**: разметка ссылается на имена файлов.
  Имя файла — номер, который видел автор фото, но истина в разметке:
  например, `PO5881.jpg` на самом деле `PC5381`.
* `data/labels/labels.json`:

  ```json
  {"images": {"AG2938": {"file": "AG2938.jpg", "width": 3000, "height": 4000,
     "plates": [{"cls": "front", "text": "AG2938", "complete": true, "uncertain": false,
                 "operator": "whoosh", "src": "exact", "pts": [[x,y],[x,y],[x,y],[x,y]]}]}}}
  ```

  * `pts` — углы таблички в пикселях фото после поворота по EXIF: левый верхний угол
    *текста*, правый верхний, правый нижний, левый нижний. Порядок задаёт направление чтения.
  * `text` — то, что физически читается на табличке; у неполной таблички это часть номера.
  * `complete: false` — номер виден не весь: в обучение чтения не идёт, в метриках не считается.
  * `uncertain: true` — читается с трудом: в обучение чтения не идёт.
  * `cls` — `front` (стойка) или `rear` (заднее крыло, две строки).
* `data/labels/split.json` — какие фото в train / val / test. Фото, на которых виден один
  и тот же самокат, всегда в одной части.

**Как добавить фото.** Положите их в `data/raw/`, добавьте записи в `labels.json`
(углы можно снять в любом редакторе картинок или взять из `whoosh-lpr --json` и поправить),
затем запустите `python training/export_yolo.py --resplit`, чтобы заново разбить фото
на части, и обучите модели. После `--resplit` тестовая часть другая, и цифры
нельзя напрямую сравнивать с прежними.

## 9. Частые проблемы

| Симптом | Что делать |
|---|---|
| `permission denied ... docker.sock` | добавьте пользователя в группу `docker` и перелогиньтесь |
| `scripts/train.sh: Permission denied` | `chmod +x scripts/*.sh` (бывает при клонировании на Windows) |
| `/usr/bin/env: 'bash\r'` | файлы получили окончания строк Windows: клонируйте внутри WSL, а не из Windows |
| `could not select device driver "" with capabilities: [[gpu]]` | не настроен NVIDIA Container Toolkit (раздел 4.3) |
| `CUDA out of memory` | мало видеопамяти: запустите шаги вручную с `--batch 4` / `--batch 96` (раздел 7.3) |
| `Bus error` или `DataLoader worker ... killed` | мало общей памяти контейнера: в `scripts/train.sh` увеличьте `--shm-size` или добавьте `--workers 2` |
| Modal: `Could not connect to the Modal server`, зависает `modal deploy` | нестабильная сеть; повторите. Запущенное обучение при этом не теряется |
| ожидание Modal прервалось | `python training/modal_app.py download --run <имя> --stage ocr` (раздел 4.4) |
| `docker build` падает на загрузке ONNX Runtime с GitHub | нет доступа к github.com из сборки; повторите или укажите `-DORT_ROOT` (раздел 7.1) |
| программа пишет «номер не найден» | табличка слишком мелкая, размытая или закрыта; снимите ближе, номер должен занимать хотя бы ~1/10 ширины кадра |

## 10. Точность и ограничения

Готовые модели (`models/`) на отложенных тестовых фото: прочитано **28 из 29** номеров,
1 лишний номер, **22 из 23** фото разобраны полностью верно. Тестовых фото немного,
поэтому погрешность у этих цифр в несколько процентов.

Известные слабые места:

* стёртый трафарет: `3` иногда читается как `8`, причём уверенно;
* сильно испорченные или закрашенные номера;
* задних табличек в данных мало (15), их чтение проверено слабо;
* все фото из одного города; первая буква в данных только `A` или `P`.

Лучший способ улучшить точность — новые фото, особенно стёртых номеров и задних табличек:
добавьте их и разметку (раздел 8) и переобучите.
